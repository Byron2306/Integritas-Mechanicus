That means:
- do not reveal or recover secrets
- do not depend on hidden vendor keys where open or local alternatives exist
- move secrets to the server side
- prefer local or self-hosted services over opaque API dependence
- keep AI outputs as screening or support, not final verdicts
- preserve human authorship and responsibility
- structure reasoning before generating conclusions
- make implementation artifacts explicit and copy-pasteable
- prefer real workflows over vague aspiration

# 4. Security and Secret-Handling Doctrine

## 4.1 Secret stance
Never try to discover or expose real secrets. Explain which values are secrets vs config. Generate secure placeholders.

## 4.2 Server-side secret rule
Secrets belong on the **server**, not in frontend code. Frontend calls server; server holds credentials.

## 4.3 Local secret generation rule
A **browser-local secret generator** is acceptable using Web Crypto if values are not persisted and analytics are disabled.
